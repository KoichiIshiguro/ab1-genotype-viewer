# AB1 Genotype Viewer

**サンガーシーケンスの `.ab1` ファイルから、狙った位置の遺伝型（ホモ／ヘテロ）を判定して Excel にまとめるローカル完結のWebツール。**

ブラウザで `index.html` を開くだけで動きます。インストール・サーバー・ネットワーク接続は不要で、
AB1データは一切外部に送信されません。

📖 **[使い方・解説ページ（help.html）](help.html)** ── ユースケース、設定項目、判定のしくみ、制限事項

---

## これは何をするツールか

サンガーシーケンス（キャピラリーシーケンス）の `.ab1` ファイルには、A／T／G／C 4色の蛍光波形が入っています。
SNPタイピングでは、この波形の**ある1か所**を見て、

- ピークが1本だけ → その塩基の**ホモ接合**（例 `G/G`）
- ピークが2本重なっている → **ヘテロ接合**（例 `A/G`）

を読み取ります。従来は1ファイルずつビューアで開き、目で波形を追い、判定を手でExcelに転記する作業でした。
サンプルが数十件あると時間がかかるうえ、

- Reverseプライマーで読んだサンプルは配列が逆向き・相補鎖になっている
- リードごとに読み始めがずれるので、目的の位置がファイルごとに違う座標にある
- 第2ピークが小さいヘテロは見落としやすく、判定が人によってぶれる

という間違いやすい要素が揃っています。

このツールは、**複数のAB1をまとめて読み込み、向きを自動で揃え、目的の位置をピーク高さの比率で数値判定して、
一覧とExcelにする**ところまでを自動化します。「波形の目視判定」を「比率による数値判定」に置き換えるのが趣旨です。

## こんなときに使う

| ユースケース | 使い方 |
|---|---|
| **SNPジェノタイピングの結果判定** | 多型のある1か所について、検体ごとの遺伝型（A/A・A/G・G/G）を一覧で得る。もっとも想定している使い方 |
| **変異導入・クローニングの確認** | 狙った塩基が入っているか、片アレルだけか（ヘテロか）を確認する |
| **配列全体の二重ピーク確認** | ターゲット配列を空欄にして解析すると、全塩基について二重ピークの有無を調べる。単一クローンかどうかの確認に使う |
| **大量サンプルの一次スクリーニング** | 判定が付いたものと「要確認」になったものに仕分けし、要確認だけ波形を目視する |

## クイックスタート

1. このリポジトリをダウンロード（またはクローン）する
2. `index.html` をブラウザ（Safari／Chrome）で**ダブルクリックして開く**
3. `.ab1` / `.abi` ファイルを画面上部にドラッグ＆ドロップ（複数可）
4. 必要ならターゲット配列を角括弧記法で入力する（例: `ATCGCCATG[A/G]ATTCCT`）
5. 「ターゲットを解析」を押す
6. 「Excelで一括出力」で `.xlsx` をダウンロード

ターゲット配列の入力欄は**既定で空欄**で、2つのモードがあります。

| ターゲット配列 | 動作 |
|---|---|
| 指定あり | 角括弧の位置1か所について、方向を自動判定して揃えたうえで遺伝型を判定する |
| 未指定（空欄） | 照合も方向判定もせず、各ファイルを読まれたまま表示し、**全塩基位置についてホモ／ヘテロを判定**する |

### ターゲット配列の書き方

判定したい1か所を角括弧で囲み、前後の配列と一緒に貼り付けます。前後の配列は、
どのサンプルがどこを読んでいるかを突き合わせる目印に使います。

```
ATCGCCATG[A/G]ATTCCTGAC…
```

- 角括弧は1か所のみ、候補塩基は2種類まで
- 角括弧の前後はそれぞれ8塩基以上（実際には30〜80塩基ずつあると安定）
- Forward鎖・Reverse鎖のどちらで書いてもよい（サンプルの向きは自動判定）

## 判定のしくみ

1. サンプル配列を、ターゲット配列に対して**そのまま**と**逆相補**の両方で照合し、よく一致したほうを採用する
   （ギャップなしスライド照合。一致 +1／不一致 −1／`N` ±0）
2. 角括弧に対応する位置の塩基について、**ピーク位置における4チャンネルの蛍光強度**を読む
3. 合計強度が**最小蛍光強度**未満なら `N`（判定不能）
4. 4つの比率（合計1.0に正規化）のうち、**最小コール比率以上**のものを候補とする
5. 候補1つ → ホモ／候補2つ → ヘテロ／候補3つ以上 → 要確認

Reverseのサンプルは、配列・ピーク位置・4色チャンネルすべてを逆相補変換してターゲットと同じ向きに揃えます。
元の読取方向は Forward／Reverse として保持・出力されます。

### Quality score は判定に使っていません

Phred quality score の算出指標のひとつが「コールされなかった塩基の最大ピーク高 ÷ コールされた塩基のピーク高」で、
これはヘテロ判定に使う第2ピーク比率とほぼ同じものです。つまり**ヘテロ位置では原理的に Quality が下がる**ため、
Quality で足切りすると探している対象そのものを捨てることになります。実データでも Q と第2ピーク比率は
はっきり逆相関しました（Q40以上で中央値 0.025、Q10–14 で 0.333）。

よって Quality score はツールチップ・詳細欄・Excelに表示するだけで、判定には使いません。
シグナルの弱い位置を外す役割は**最小蛍光強度**が担います。

## ターゲット未指定モード

読めている全塩基位置に同じ基準を当て、閾値以上の塩基が2種類ある位置（＝ヘテロ）を拾います。

- **最小蛍光強度**を満たす位置だけを判定対象にする
- 判定した位置は配列上で強調表示し、詳細欄に一覧を出す（クリックでその位置へ移動）
- Excelは**ヘテロ位置1つにつき1行**で出力する（0箇所のサンプルは要約1行）

> ⚠️ 比率だけで判定するため、**色素のにじみ（bleed-through）やベースラインの持ち上がりもヘテロとして拾います。**
> とくに読み始め50塩基付近に集中します（実データでは、品質の良いリードで全長11箇所中9箇所が先頭50塩基以内）。
> 検出された位置は必ず波形を確認してください。

## Excel出力（19列）

`サンプル名 / 元ファイル名 / ターゲット名 / 判定 / 遺伝型 / 実測対象塩基 / 位置 /
A比率 / T比率 / G比率 / C比率 / A蛍光強度 / T蛍光強度 / G蛍光強度 / C蛍光強度 /
Quality score / 元の読取方向 / アライメント可否 / コメント`

比率は 0〜1 の小数（小数第4位）。xlsx は外部ライブラリを使わず自前で生成しているため、オフラインでも動きます。

## 実装仕様・既定値

| 項目 | 決めた内容 |
|---|---|
| 強度指標 | 対象位置のピーク位置における **A/T/G/C 4チャンネルの合計値**（負値は0に丸める）。比率の分母と一致させるため合計を採用。最大ピーク高を基準にするとヘテロ接合体が不利になる |
| 最小蛍光強度 の既定値 | `500`（画面で変更可） |
| 最小コール比率 の既定値 | `0.20`（判定は「以上」。0.20ちょうどは採用する） |
| Quality score の扱い | **閾値を設けない。**理由は上記。値は表示のみ |
| アライメント採用基準 | ギャップなしスライド照合。一致率の下限 `0.80`（画面で変更可）、比較できた塩基数 30以上。`N` は加点も減点もしない |
| 遺伝型の表記順 | `A/T/G/C` の順に固定（比率の大小順ではない） |
| ターゲット未指定時の判定対象 | 最小蛍光強度を満たす位置のみ。方向判定・アライメントは行わない |
| Excelの比率表記 | **小数**（0〜1、小数第4位）で統一 |
| 重複読込の判定キー | **ファイル名**で判定して追加を拒否する。AB1内サンプル名の重複は警告のみ（別ファイルとして読み込む） |
| 角括弧の制約 | 1か所のみ、候補塩基は2種類まで、前後はそれぞれ8塩基以上 |

## 区別して表示・出力する状態

判定が出せない場合も、理由を区別して表示・出力します。黙って空欄にはしません。

| 状態 | 表示 |
|---|---|
| AB1読込失敗 | 読込失敗（理由を併記） |
| 配列・波形・品質データ不足 | 読込失敗／`Quality scoreがファイルに含まれていません` |
| ベースコールが1塩基もない | `ベースコールされた塩基がありません（シーケンス失敗）` |
| アライメント不可 | `ターゲットシーケンスとアライメントできませんでした` |
| 対象位置まで読めていない | `対象位置を判読できません` |
| 最小蛍光強度未満 | `N`／判定不能 |
| 3塩基以上の混合ピーク | 要確認 |
| 重複読込 | 警告（追加しない） |
| 角括弧で指定していない塩基を検出 | 要確認フラグ |

## 読んでいるABIFタグ

`PBAS1/2`（ベースコール）、`PLOC1/2`（ピーク位置）、`PCON1/2`（Quality score）、
`DATA9-12`（解析済み4色波形）、`FWO_`（チャンネルと塩基の対応順）、`SMPL`／`MCHN`／`S/N%`。

`FWO_` はファイルごとに読みます（固定値を仮定すると、機種によってチャンネルの対応が入れ替わるため）。

## ファイル構成

```
index.html        画面（バージョン表記はタイトル横の <span class="ver">。package.json と合わせて更新する）
help.html         使い方・解説ページ
js/abif.js        ABIF(.ab1/.abi)パーサ、逆相補変換
js/target.js      角括弧記法のパース
js/align.js       順方向／逆相補方向の照合と方向判定
js/call.js        対象位置の強度・比率・遺伝型判定
js/xlsx.js        依存なしの最小 .xlsx ライター（ZIP store + SpreadsheetML）
js/export.js      Excel 19列の行データ生成
js/app.js         画面の組み立てと操作
test/             検証スクリプト
```

依存ライブラリはありません。`js/*.js` はブラウザのクラシックスクリプトとしても
Node の `require()` としても読める形にしてあり、テストは Node だけで動きます。

## テスト

```
node test/rules_test.js      # 判定ルール（15件）
node test/validate.js        # 同階層の実AB1で解析 + 逆相補変換・Reverse経路・未指定モードの検証
node test/export_test.js     # 実データから .xlsx を生成
```

`test/validate.js` と `test/export_test.js` は、リポジトリ直下に `.ab1` ファイルが置いてある前提で動きます。
**実験データは個人の検体データを含むためリポジトリには含めていません**（`.gitignore` で除外）。
手元の `.ab1` を直下に置いてから実行してください。

`test/ui_check.html` は画面の寸法・描画を確認するための補助ページで、
ローカルHTTPサーバー経由でのみ動きます（`python3 -m http.server` → `/test/ui_check.html`）。

## 現時点で対応していないこと

- 挿入・欠失（indel）。照合はギャップなしのため、indelを含むリードは一致率が下がる
- 複数座位のターゲット一括登録（`js/target.js` の `parseAll()` は複数行＝複数ターゲットを返す構成にはしてある）
- 同一検体の Forward / Reverse の自動対応付けと一致判定
- クロマトグラムのPNG／PDF保存、解析条件や手動修正の履歴保存、PDFレポート
